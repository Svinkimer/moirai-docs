# Командная разработка

Moirai Editor пока не имеет встроенной системы командной работы с общей базой данных, ролями и одновременным редактированием одного проекта несколькими авторами.

Тем не менее, над проектом можно работать командой, если заранее договориться о процессе.

## Главный принцип

Не редактируйте один и тот же проект одновременно из разных копий редактора без согласованного порядка обмена изменениями.

Если два человека независимо изменят один проект, а затем попытаются объединить результаты вручную, часть работы легко потерять. Особенно это касается сцен, графа, персонажей и ассетов.

## Рекомендуемый простой процесс

Для небольшой команды удобнее всего назначить одного человека ответственным за сборку проекта.

Примерный процесс:

1. Сценаристы пишут текст и структуру сцен в отдельном документе.
2. Художники и звукорежиссёр готовят ассеты.
3. Ответственный редактор добавляет материалы в Moirai Editor.
4. Команда регулярно получает экспортированный `.vnproject` для тестирования.
5. Все замечания собираются в одном месте: документе, таблице, таск-трекере или чате.
6. Ответственный редактор вносит правки и снова экспортирует актуальную версию.

Такой подход не самый автоматизированный, зато он снижает риск случайно перезаписать чужую работу.

## Работа через экспорт проекта

Файл `.vnproject` удобно использовать как переносимую версию проекта.

Через него можно:

- передать проект другому участнику команды;
- отправить проект на тестирование;
- сохранить контрольную версию перед крупными изменениями;
- приложить проект к обращению в поддержку;
- перенести работу на другое устройство.

Перед отправкой проекта убедитесь, что он открывается в редакторе и запускается хотя бы со стартовой сцены.

## Резервные копии

Перед крупными правками создавайте резервную копию проекта.

Особенно полезно делать копию перед тем, как вы:

- меняете граф истории;
- переименовываете сцены;
- удаляете персонажей или локации;
- массово заменяете ассеты;
- добавляете сложное ветвление;
- готовите проект к публикации.

В названии копии удобно указывать дату и короткое описание:

- `project_2026-07-06_before_branching.vnproject`
- `project_2026-07-06_after_dialogue_polish.vnproject`
- `project_2026-07-06_release_candidate.vnproject`

## Использование Git

Если в команде есть человек, который умеет работать с Git, проект можно хранить в репозитории.

Это полезно, потому что Git позволяет:

- видеть историю изменений;
- возвращаться к прошлым версиям;
- хранить стабильные сборки;
- фиксировать версии перед тестированием;
- не терять проект при ошибках.

Однако Git не превращает Moirai Editor в систему одновременного редактирования. Даже с Git лучше договориться, кто и когда меняет проект, чтобы не создавать конфликтующие версии.

## Разделение задач

Чтобы команда работала спокойнее, разделяйте задачи по зонам ответственности.

Например:

- один человек отвечает за граф истории;
- один - за перенос диалогов;
- один - за ассеты персонажей;
- один - за музыку и SFX;
- один - за тестирование веток;
- один - за финальную сборку.

Чем меньше людей одновременно меняют одну и ту же часть проекта, тем проще поддерживать порядок.

## Тестирование командных изменений

После каждой крупной порции правок проверяйте проект как игрок:

- запускается ли стартовая сцена;
- работают ли переходы в графе;
- нет ли недостижимых сцен;
- не появились ли тупики;
- все ли ассеты отображаются;
- воспроизводится ли музыка;
- работают ли выборы и условия;
- можно ли дойти до нужных концовок.

Если проект сломался, проще найти причину сразу после небольшой серии изменений, чем после недели активной работы всей команды.

## Что лучше не делать

Мы не рекомендуем:

- пересылать друг другу отдельные куски `project.json`;
- вручную менять содержимое `.vnproject`;
- одновременно редактировать разные копии одного проекта и потом пытаться объединить их “на глаз”;
- удалять ассеты, не проверив, используются ли они в сценах;
- вручную изменять технические ID: для работы с проектом используйте понятные авторские названия сцен и переменных.

Moirai создавался как no-code инструмент, поэтому самый безопасный способ работы с проектом - через интерфейс редактора.
